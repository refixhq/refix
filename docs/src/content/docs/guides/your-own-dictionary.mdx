The `refix` command-line tool generates [typed messages](/guides/typed-messages/) from your own FIX dictionary.

- It reads a dictionary in QuickFIX's XML format, with the custom messages, fields, values and groups it defines.
- It writes a Python package, a Rust module or both, each with a file for every message and component.
- It accepts a dictionary with common defects, and prints a warning for each thing it dropped or changed.

## Install the tool

```sh
uv tool install refix-cli
```

This installs a prebuilt binary. With a Rust toolchain, `cargo install refix-cli` builds it from source.

## Generate the code

```sh
refix codegen venue.xml --python venue --rust src/venue
```

Give `--python`, `--rust` or both, each with the directory to write. The directory has the name of the package or
module, so this one is imported as `venue` in Python and declared as `mod venue;` in Rust.

Do not edit the generated files. Run the tool again when the dictionary changes. It removes the files of messages
and components that are gone from the dictionary, and leaves any file it did not generate.

## Other FIX versions

FIX 4.2 and 4.4 have ready-made packages. For another version, generate the code from QuickFIX's dictionary for
it, found in its [spec directory](https://github.com/quickfix/quickfix/tree/master/spec). For FIX 4.0, 4.1 or 4.3:

```sh
refix codegen FIX43.xml --python fix43 --rust src/fix43
```

From FIX 5.0 the header, the trailer and the session messages, such as Logon, are in a transport dictionary of
their own, `FIXT11.xml`. Give it with `--transport`:

```sh
refix codegen FIX50SP2.xml --transport FIXT11.xml --python fix50sp2 --rust src/fix50sp2
```

This works for FIX 5.0, 5.0 SP1 and 5.0 SP2. QuickFIX's `FIX50SP2.xml` also holds every extension pack released
since SP2, so it gives about 890 files in each language.

Those dictionaries are under the QuickFIX Software License.

## Use the code

In these examples the dictionary gives NewOrderSingle a custom DeskID (5001) field.

<Tabs syncKey="language">
	<TabItem label="Python">
		Put the `venue` directory where your code can import it. It needs the `refix` package.

		```python
		import refix
		from venue import CODEC, NewOrderSingle

		for record in refix.decode_log("session.log", CODEC):
		    order = record.message
		    if isinstance(order, NewOrderSingle):
		        print(order.cl_ord_id, order.desk_id)
		```

		Every name is imported from `venue`. `venue.messages`, `venue.components` and `venue.enums` hold the same
		names by kind.
	</TabItem>
	<TabItem label="Rust">
		Generate into `src/venue` and declare the module. It needs the `refix-message` crate, so run
		`cargo add refix-message`.

		```rust
		#[allow(dead_code)]
		mod venue;

		use refix::message::LogReader;
		use venue::{DIALECT, Message};

		fn main() -> Result<(), Box<dyn std::error::Error>> {
		    let mut reader = LogReader::new(DIALECT, None);
		    reader.feed(&std::fs::read("session.log")?);
		    for record in reader.finish() {
		        if let Message::NewOrderSingle(order) = Message::from_raw(record.message) {
		            println!("{:?} {:?}", order.cl_ord_id()?, order.desk_id()?);
		        }
		    }
		    Ok(())
		}
		```

		Without `#[allow(dead_code)]`, a binary gets a warning for each generated item it does not use. Every name is
		imported from `venue`, as the files inside it are private modules.
	</TabItem>
</Tabs>

The code is used like the FIX 4.4 package in [Typed messages](/guides/typed-messages/).

## How names are derived

| In the dictionary                 | Python                         | Rust                          |
| --------------------------------- | ------------------------------ | ----------------------------- |
| Message `NewOrderSingle`          | `NewOrderSingle`               | `NewOrderSingle`              |
| Field `DeskID`                    | `desk_id`                      | `desk_id()`                   |
| Field `SettlCycle`                | `settl_cycle`                  | `settl_cycle()`               |
| Its values, as an enum            | `SettlCycle`                   | `SettlCycle`                  |
| Value `SAME_DAY`                  | `SettlCycle.SAME_DAY`          | `SettlCycle::SameDay`         |
| Component `Instrument`            | `instrument`                   | `instrument()`                |
| Its type                          | `Instrument`                   | `Instrument`                  |
| Group `NoAllocAccounts`           | `alloc_accounts`               | `alloc_accounts()`            |
| One instance, in `NewOrderSingle` | `NewOrderSingle.AllocAccounts` | `NewOrderSingleAllocAccounts` |

A component that holds only a group gives its own name to the instances, such as `Parties`.

Some names need a change to be valid or unique:

- A value whose description starts with a digit gets an `N` in front. `2_DAYS` becomes `N_2_DAYS` in Python and
  `N2Days` in Rust.
- An enum with the same name as a message gets `Enum` on the end, such as `SecurityStatusEnum`.
- Two values of one field with the same description are numbered, such as `EURIBOR` and `EURIBOR_2` in Python, and
  `Euribor` and `Euribor2` in Rust.

## Warnings and errors

A defect that leaves the dictionary usable is a warning, and the code is still generated.

```text
warning: message 'VenueStatus' has unknown msgcat 'venue', which is read as app
```

| Defect                                              | What the tool does                 |
| --------------------------------------------------- | ---------------------------------- |
| A message or component lists a tag twice            | Keeps the first and drops the rest |
| A value code is listed twice for one field          | Keeps the first and drops the rest |
| A message's `msgcat` is not `admin` or `app`        | Reads it as `app`                  |
| The XML declaration is not at the start of the file | Ignores it                         |

Any other problem stops the tool with an error that names it.

```text
error: cannot parse 'venue.xml': message 'VenueStatus' references unknown field 'NoSuchField'
```

A tag listed both inside a repeating group and outside it is one of these errors, as a reader could not tell which
of the two a field belongs to.
